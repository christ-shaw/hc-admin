# 客户名称推荐（2026-09-11）

## 范围与行为

- 新建、编辑订单共用 `CustomerNameField`，原独立关联区域收进“更多操作”。输入客户名称 300 ms 后按主名称或有效别名查询，最多展示 3 个不同的有效客户，顺序为完全匹配、前缀匹配、包含匹配，再按更新时间和 ID 稳定排序。
- 卡片展示主名称、最多 3 个别名、常用收件人与地址。别名可直接选用；多地址入口按 20 条分页。选中客户或别名后，收件信息为空时自动带入常用收货档案；已有不同的非空信息（包括仅填写部分字段）时先确认再覆盖。取消覆盖会保留新选客户及别名关联和原收件信息；完全相同的信息无需重复确认。客户没有收货档案时仅关联客户。“使用此地址”和其他地址选择沿用相同覆盖确认规则。打开已有订单、只修改名称文字不会自动带入地址。
- 输入法组合期间不查询；空输入不查询；迟到请求不能覆盖新结果；同一表单内 15 秒缓存、最多 20 个查询键。无结果或请求失败允许自由填写。
- 推荐列表在名称输入框下方按正常布局展开，撑开表单内容，随弹窗滚动；不使用绝对定位浮层或列表内嵌滚动，避免被弹窗裁切或覆盖后续字段。
- 新建订单未选择时显式提交 `customerSelectionMode=none`，不自动建档或自动关联。其他导入及衍生订单入口继续沿用原逻辑。
- 编辑时，单纯修改文字保持旧关联；明确选择或取消后，保存订单才更新关联。提交原 customerId/customerAliasId/recipientProfileId，用于检测并发改绑。服务端校验目标可用性、子资料所属客户，关联与订单、审计同事务提交。收件快照临时调整不会修改客户档案；与档案不一致的引用在显式选择保存时清除。
- 新查询仅返回选择所需的字段，不返回客户备注、历史订单或审计；保留订单新增/编辑角色的受限查询权限。快捷建档和维护档案仍要求 customers:write。

## 接口与部署

1. 更新 `manageCustomers`：新增 `search / scope=orderSuggestions`，响应包含客户名称、别名、地址摘要。旧 search/get 行为保留。
2. 更新 `updateOrder`：支持显式关联变更及原引用校验，普通旧表单依旧不能直接覆盖关联元数据。
3. 发布前端：Orders、CustomerNameField、useCustomers、useOrders 和类型。先部署云函数后发布前端；旧云端会拒绝新查询或忽略编辑关联，不能仅发布前端。

2026-09-11 联调时确认云端旧版 manageCustomers 拒绝 orderSuggestions（ACTION_NOT_ALLOWED）。已更新 manageCustomers、updateOrder；同时发现 saveOrders 缺少阶段 4 的 customerSelectionMode 支持，已补充部署。前端目前在本地运行，尚未发布线上；顺丰云函数无需更新。部署前代码包备份保存在 `/tmp/hc-customer-release-20260911/backup/`。

查询在数据库按名称/别名过滤后进行排序，收货档案只加载入选的 3 个客户。包含查询仍是正则过滤，高匹配量下需要扫描匹配结果；后续若数据规模显著增加，可采用专用搜索索引，不能宣称恒定查询耗时。
