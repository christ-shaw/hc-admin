# 随单建档复用录单检查

录单阶段仍检查当前名称及收件信息。`manageCustomers.matchIdentity` 的 `orderArchive` 范围要求建档权限；检查没有候选且资料可用时，在现有服务端 `customer_write_requests` 集合中保存结果凭据，并返回 `archiveCheckId`。普通匹配和批量归档接口不变。

前端仅为当前输入保留凭据，修改名称、收件人、手机号或地址后，原结果失效，在填写阶段重新检查。提交订单带上 `customerArchiveCheckId`；`saveOrders` 随单建档按 ID 读取凭据，验证操作人、本单身份信息及单次使用限制，直接复用检查结论，不再扫描客户、别名和收货档案，也不因客户库版本变化而重新查重。

这采用的是填写阶段的查重结论：检查完成后其他人新建的相同客户不会在本次提交时再次发现。不同录单各自取得的有效结果也不承诺全局去重。

凭据与建档在同一个事务内绑定订单，失败可重试；同一凭据不能用于两张订单建档，同一订单重复建档返回已有关联。凭据错误或内容不符时订单保留、档案待处理，不退回全量扫描。没有凭据的旧客户端及历史订单继续走原有查重流程，以支持分步发布。

部署顺序：先更新 `manageCustomers` 和 `saveOrders`，再更新前端。不需要新建集合或索引。共享模块由 `scripts/sync-customer-order-modules.cjs` 同步；其余函数中的变更仅阻止客户端注入内部凭据字段。

验证：`npm run test:customers` 覆盖复用且无全量读取、客户库版本变化、输入改变、伪造与跨用户凭据、单次使用、失败后重试及旧流程兼容；`npm run build` 检查类型与前端构建。
