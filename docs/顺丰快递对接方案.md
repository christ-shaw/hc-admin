# 顺丰快递对接方案

> 当前版本：V2
>
> 切换日期：2026-07-24
> 当前范围：普通顺丰单、查询、取消、模板导出、丰密面单打印

## 1. 目标

顺丰业务数据与业务订单解耦。`orders` 只保存通用物流结果，顺丰申请过程、环境、请求结果和打印统计统一保存到独立集合。

本期不处理历史顺丰数据迁移，不实现子母单和签回单。

## 2. 数据模型

### 2.1 `orders`

顺丰流程只允许维护以下通用物流字段：

- `trackingNumber`
- `expressProvider`
- 已存在的通用 `shippingFee`

顺丰下单或查询恢复成功只写入运单号与承运商，不将 `status` 改为
`shipped`。`status='shipped'` 表示仓库已完成出库，由 `completeOutbound`
在实际交货时写入。

旧的 `sfEnv`、`sfOrderId`、`sfWaybillNo`、`expressApplyStatus`、`sfPrintCount`、`sfExportCount` 等字段不删除，但 V2 不再读取或写入。

### 2.2 `sf_express_orders`

每个顺丰客户订单号一条记录：

```ts
interface SfExpressOrderRecord {
  _id: string; // sha256(env:sourceOrderId:attemptNo)
  sourceOrderId: string;
  sourceSerialNumber: number;
  sourceOnlineOrderNumber: string;
  sourceOrderDate: string;
  sfOrderId: string;
  attemptNo: number;
  env: 'sandbox' | 'production';
  isCurrent: boolean;
  status: 'applying' | 'applied' | 'failed' | 'cancelled';
  waybillNo: string;
  waybillNoInfoList: Array<{ waybillType?: string | number; waybillNo: string }>;
  applyRequestId: string;
  searchRequestId: string;
  cancelRequestId: string;
  applyTime: string;
  cancelTime: string;
  errorCode: string;
  errorMessage: string;
  orderSnapshot: object;
  senderSnapshot: object;
  requestSummary: string;
  responseSummary: string;
  printCount: number;
  lastPrintTime: string;
  lastPrintRequestId: string;
  operatorId: string;
  createdAt: string;
  updatedAt: string;
}
```

请求/响应摘要先递归移除 Token/Authorization，并对电话脱敏，序列化后最多保存 64 KiB。`accessToken` 永不写入业务集合和打印日志。

索引：

- 唯一：`env + sfOrderId`
- 普通：`sourceOrderId + env + isCurrent`
- 普通：`env + waybillNo`
- 普通：`sourceOrderDate + env + createdAt`

失败重试复用原记录和原 `sfOrderId`。取消后重新下单创建下一条记录，`attemptNo` 递增，客户订单号追加 `_2`、`_3`。

### 2.3 `sf_export_logs`

每个“导出批次 + 来源订单”一条日志。确定性 `_id` 与唯一索引共同保证同一批次重试不重复计数。

索引：

- 唯一：`exportBatchId + sourceOrderId`
- 普通：`sourceOrderId + exportedAt`

### 2.4 `sf_print_logs`

PDF 和插件打印日志均保存：

- `sfExpressOrderId`
- `sourceOrderId`
- `requestID`
- `waybillNo`
- 环境、渠道、结果和操作人

打印成功后更新 `sf_express_orders.printCount`，不再更新订单表。

## 3. 状态与关联

正式关联键是 `sourceOrderId = orders._id`。页面序号和网店订单号只保存为快照。

工作台主状态只看当前 `system_config/sf_express.env`：

- `not_required`：无需顺丰
- `not_created`：未下单
- `applying`：申请中
- `applied`：申请成功
- `failed`：申请失败
- `cancelled`：已取消
- `other_express`：已有其他快递
- `legacy_unmanaged`：V2 切换日前且没有独立记录，或仅有旧顺丰通用物流结果

其他环境的当前记录只作为提示徽标，不影响当前环境状态和操作按钮。

## 4. 云函数接口

### 4.1 `applySfExpress`

请求：

```json
{ "sourceOrderId": "orders._id" }
```

流程：

1. 读取 V2 开关、当前顺丰环境和来源订单。
2. 同环境存在 `applied/applying` 当前记录时拒绝重复下单。
3. `failed` 重试原记录；`cancelled` 创建下一 attempt。
4. 先将顺丰记录置为 `applying`，再调用 `EXP_RECE_CREATE_ORDER`。
5. 成功后事务更新顺丰记录，并向订单写入 `trackingNumber` 与
   `expressProvider='sf'`；保持订单原发货状态。订单已关联待出库记录时，
   同一事务自动补写出库记录的 `trackingNumber`；已有不同单号时不覆盖并返回冲突提示。
6. 失败仅更新顺丰记录；不污染订单表。
7. 网络不确定或重复单查询失败时保留原客户订单号供查询恢复，避免重复下单。

### 4.2 `querySfOrderResult`

请求：

```json
{ "sfExpressOrderId": "sf_express_orders._id", "searchType": "1" }
```

查询成功后事务更新独立顺丰记录，并恢复订单的 `trackingNumber` 与
`expressProvider='sf'`，同时补写已关联的待出库记录，但不标记实际发货。查询失败只更新独立记录；
已经成功或取消的主状态不会被失败查询覆盖。

### 4.3 `cancelSfExpress`

请求：

```json
{ "sfExpressOrderId": "sf_express_orders._id" }
```

取消成功后保留历史运单信息并将顺丰记录置为 `cancelled`。只有当订单当前 `trackingNumber` 仍等于该顺丰运单号且 `expressProvider=sf` 时，才清空订单通用物流字段；已关联待出库记录中的相同单号同步清空。关联出库记录已经完成时禁止取消，已完成记录永不自动改写。

### 4.4 `querySfExpressOrders`

请求：

```json
{
  "date": "2026-07-24",
  "limit": 20,
  "cursor": null,
  "serialNumber": "",
  "onlineOrderNumber": "",
  "consignee": "",
  "salesperson": "",
  "shippingFee": ""
}
```

接口先按 `orders.date` 直接分页，再批量关联顺丰记录和导出日志。返回独立 DTO：

`orders` 已增加普通索引 `date + serialNumber(desc)`，保证按日期分页和排序不会回退为全表扫描。

```ts
interface SfExpressWorkbenchRow {
  order: OrderRecord;
  sfStatus: SfWorkbenchStatus;
  currentSfOrder: SfExpressOrderRecord | null;
  otherEnvSummary: object[];
  exportSummary: { count: number; lastExportTime: string };
}
```

顺丰专属字段不会重新塞回 `OrderRecord`。

### 4.5 `recordSfExport`

请求包含 `orderIds` 和前端生成的 `exportBatchId`。同一批次重复调用时返回重复数，不新增重复日志。

## 5. 环境和 V2 开关

配置文档：

```json
{
  "_id": "sf_express",
  "env": "sandbox",
  "dataModelVersion": 2,
  "dataModelCutoverDate": "2026-07-24",
  "pluginPrintEnabledByEnv": {
    "sandbox": true,
    "production": false
  }
}
```

`applySfExpress` 在 `dataModelVersion !== 2` 时拒绝新下单，避免部署窗口内提前写入。工作台也会禁用生成按钮。

客户编码、校验码、月结卡号、寄件人、打印模板继续通过云函数环境变量维护：

```text
SF_CLIENT_CODE
SF_SANDBOX_CLIENT_CODE
SF_PROD_CLIENT_CODE
SF_SANDBOX_CHECK_WORD
SF_PROD_CHECK_WORD
SF_MONTHLY_CARD
SF_SENDER_MAP
SF_PRINT_TEMPLATE_CODE
SF_SANDBOX_PRINT_TEMPLATE_CODE
SF_PROD_PRINT_TEMPLATE_CODE
```

`sf_tokens/sandbox` 和 `sf_tokens/production` 仅作为后端 Token 缓存。

## 6. 工作台交互

顺丰页面不再分“待处理/订单记录”标签。默认显示今天，可切换单个日期，20 条分页。

操作规则：

- 未下单：生成顺丰单
- 申请中：查询
- 申请失败：查询、重试
- 申请成功：查询、打印、取消
- 已取消：重新生成
- 无需顺丰、其他快递、历史未纳入：不提供下单操作

## 7. 一致性与安全

- 下单成功、查询恢复、取消均使用数据库事务维护独立顺丰记录与订单通用物流字段。
- 顺丰记录 `applied` 仅表示运单生成成功；订单 `status='shipped'` 仅由实际出库完成写入。
- 首次下单与取消重下使用确定性记录 `_id`；失败重试使用条件更新抢占记录，降低并发重复调用风险。
- 唯一索引阻止同环境重复 `sfOrderId`。
- 所有顺丰调用在后端完成；前端不接触下单接口 Token。
- `sf_express_orders` 和 `sf_export_logs` 均设置为 `ADMINONLY`，浏览器只能通过带权限校验的云函数读取。
- Windows 插件打印因顺丰 SDK 协议需要短效 Token，必须经过 `sf:print` 权限、环境开关和一次性打印会话约束。
